一、结论（总览）

事项 本版方案
总体结构 采销分离：销售线（应收）与采购线（应付）各自生成结算单、各自确认、各自在财务侧收付；履约单对账完成后不联动生成采购端付款结算
单据数量 两单制：全系统只有两张结算单——销售结算单（明细行 = 履约单）与采购结算单（明细行 = 采购单）；不另设对账单，也不拆成四张
单据内阶段 每张结算单分两个阶段：对账阶段（生成 → 确认，产出双方确认的结算金额）与结算阶段（开票 / 收票、收款 / 付款 → 办结）
职责分工 对账阶段归业务（销售 / 采购），结算阶段归财务；合作商在终端确认对账
销售端客户差异 淡茶发起对账 / 客户来账 / 预存余额三种情况，同一张销售结算单承载，差别只在来源与付款方式
采购端合作商差异 签收后付款（月结 / 季结 / 周期结 / 见票结）与先款后货，同一张采购结算单承载，差别只在付款节点
采购单已结算 改为所属采购结算单办结时置位
积分 结算完成 = 采购结算单已办结，且对应履约单客户回款到位（待确认 6）
三项补强 阶段显性化（两段式状态条、时间点、操作记录）、权限分段、命名统一
财务页面 发票管理、收款管理、付款管理由只读台账改为操作页；应收 / 应付管理保持只读台账；财务概览增加结算待办卡

二、总体结构

2.1 采销分离

销售线（应收）：履约单确收 → 销售·生成销售结算单 → 销售·确认对账 → 财务·开票 + 收款 → 销售结算单办结 → 履约单/销售单办结 采购线（应付）：采购单签收(直发)或入库 → 采购·生成采购结算单 → 合作商/采购·确认对账 → 财务·收票 + 付款 → 采购结算单办结 → 采购单已结算

  • 两条线互不触发：客户对账完成不生成采购端付款结算，采购端付款也不依赖客户回款。
  • 两侧的单据互相引用不互相生成：采购结算单明细行的关联履约单号来自采购单的 childOrderCode，仅作对照展示与积分判定，不产生单据联动。
  • 结算对象：直接销售 = 客户本人；经平台销售 = 平台客户，金额按销平台实价（订单价格快照，缺省回退客户档案现值）。

2.2 两单制：一张结算单承载对账与结算

对账与结算不是两张单据，而是同一张单据前后相接的两个阶段。明细行与金额口径从头到尾是同一份：确认对账时金额锁定，财务在其上登记开票与收付。

单据 对账阶段（业务） 结算阶段（财务） 明细行与金额
销售结算单 生成 → 发客户核对，或登记客户来账 → 确认对账（有异议则调整后重新确认） 开票登记、收款登记 → 办结 已确收履约单；计入金额 = 订单金额（直接销售）或销平台实价（经平台销售）
采购结算单 生成 → 合作商确认，或后台代确认 收票登记、付款登记 → 办结 采购单；金额 = 采购单金额

阶段是派生显示，不新增存储状态：

单据状态 待确认 / 有异议 已确认 已办结
所处阶段 对账中 结算中 已办结

是否拆成四张单据的分析见附录 A，结论是不拆。

三、命名统一

原名称里「对账单」包含开票收款、「合作商结算」里做对账确认，名实不符。统一后单据叫结算单，「对账」只作为阶段名和动作名保留。

对象 现名 统一为 说明
单据 客户对账单（CustomerStatement） 销售结算单 编号前缀 DZ-S 改为 JS-S
单据 合作商对账单（PartnerStatement） 采购结算单 编号前缀 DZ-P 改为 JS-P
金额字段 对账金额、对账净额 结算金额、结算净额 销售侧的应收余额改称未收余额
菜单 销售 → 客户对账 销售 → 销售结算 按销售结算单展示，负责确认对账
菜单 采购 → 采购管理 → 采购结算（修订一拟名，按采购单） 采购管理 → 采购单结算 与「履约单结算」对应
菜单 采购 → 采购管理 → 采购对账（修订一拟名，按结算单） 采购管理 → 采购结算 与「销售结算」对应
阶段与动作 对账、确认对账、登记异议、客户对账单号、对账中 不变 「对账」描述的是与对方核对金额这件事

五、销售端结算（应收线）

三种客户情况的差别只落在两处：结算单来源与付款方式。开票与收款不分先后，两者都覆盖结算净额时销售结算单自动办结。

5.1 流程一：淡茶发起对账（现流程沿用）

步 点哪里 做什么 结果
1 销售 → 销售单管理 → 履约单履约 对已妥投履约单点「确认收货」 履约状态 = 已确收；订单进度直接 = 结算中（G8），进入待对账
2 销售 → 销售单管理 → 履约单结算 → 待对账 勾选同一结算对象的履约单，点「生成销售结算单」，填账期说明 销售结算单待确认；明细行 = 履约单计入金额
3 线下 把结算单发客户核对回签 无
4 销售 → 销售结算 点「确认对账」；有异议点「登记异议」，调整后重新确认 销售结算单已确认，金额锁定，正式形成应收
5 财务 → 核算与其他 → 发票管理 → 待开票 开票登记（发票号 / 金额 / 日期，可分多张） 开票进度更新，履约单回写开票状态，发票进销项台账
6 财务 → 应收应付 → 收款管理 → 待回款 收款登记（金额 / 日期 / 方式，可分多笔） 收款进度更新，履约单回写已收款，回款进台账
7 无需操作 开票与收款均覆盖结算净额 销售结算单已办结 → 履约单已办结 → 销售单全部履约单办结后订单状态 = 已办结

5.2 流程二：客户提供对账单（客户来账）

步 点哪里 做什么 结果
1 同流程一 确认收货 同上
2 销售 → 销售单管理 → 履约单结算 → 待对账 勾选来账涉及的履约单，点「登记客户来账」：录客户对账单号、对账金额、账期 销售结算单待确认，来源 = 客户来账；弹窗并列展示淡茶侧计入金额与差异
2a 同一弹窗 金额有差异：录差异调整（可正可负）并填说明；或先登记异议，退回客户改账 结算净额 = 客户确认金额
3 销售 → 销售结算 核对无误后点「确认对账」；这类结算单不用再发客户确认，确认即淡茶核对通过 销售结算单已确认
4~6 同流程一 开票、收款、办结 同上

登记弹窗底部放两个按钮：「保存为待确认」和「核对无误直接确认」。

5.3 预存余额（预付客户）

步 点哪里 做什么 结果
预充 财务 → 应收应付 → 收款管理 → 预存账户 预收款登记：客户 / 金额 / 日期 / 方式 客户预存余额增加
消费 同流程一或流程二 生成并确认销售结算单，财务开票 同上
扣款 财务 → 应收应付 → 收款管理 → 待回款 收款登记，方式选「预存余额支付」，默认带出可扣金额 余额扣减，结算单核销
余额不足 同上 先用余额支付，差额再登记一笔转账 同上
  • 可扣金额取未收余额与预存余额中较小的那个。
  • 预存客户同样走结算单（沿用 2026-11-24 业务确认 3）；预收款本身不开票，开票随结算单。
  • 客户档案结算方式由文本改为选项（月结 / 季结 / 见票结算 / 预存）；结算方式为预存的客户，收款登记默认选「预存余额支付」。

六、采购端结算（应付线）

采购结算单承载全部采购单来源：合作商直发、自营以销定采、手工采购订单（G4）。付款节点分两种，默认取合作商档案的结算方式（月结 / 季结 / 周期结 / 见票结 / 先款后货），生成时可以改。

6.1 流程三：签收后付款（月结、季结、周期结、见票结）

步 点哪里 做什么 结果
1 无需操作 采购单已签收（直发）或已入库 进入待结算
2 采购 → 采购管理 → 采购单结算 → 待结算 勾选同一合作商的采购单，生成采购结算单 采购结算单待确认
3 合作商工作台 → 结算管理（或采购 → 采购管理 → 采购结算 代确认） 合作商点「确认对账」；有异议点「登记异议」 采购结算单已确认，金额锁定
4 财务 → 核算与其他 → 发票管理 → 进项发票 → 待收票 收票登记 收票进度更新
5 财务 → 应收应付 → 付款管理 → 待付款 付款登记（金额 / 日期 / 账户，可分批） 付款进度更新
6 无需操作 收票与付款均齐备 采购结算单已办结 → 采购单已结算

6.2 流程四：先款后货（预付款节点）

步 点哪里 做什么 结果
1 无需操作 合作商接单，采购单已确认且未发货 进入待预付
2 采购 → 采购管理 → 采购单结算 → 待预付 生成采购结算单，付款节点 = 发货前，带出发货前应付金额（= 结算金额 × 预付比例，默认 100%） 采购结算单待确认
3 合作商工作台 → 结算管理 合作商确认对账 采购结算单已确认
4 财务 → 应收应付 → 付款管理 → 待付款 付款登记 采购结算单已预付；采购单与合作商终端显示「预付款已到账，可发货」
5 合作商工作台 → 订单管理 发货；客户确收后采购单已签收 无
6 财务 → 发票管理 → 进项发票 收票登记 同流程三
7 无需操作，或在付款管理登记尾款 预付比例 100% 时自动办结；有尾款的登记尾款后办结 采购结算单已办结 → 采购单已结算

先款后货的三条规则：

  1. 不拦截发货：未收到预付款时，合作商点发货只弹提醒，可以继续，便于紧急放货。已发货但没预付的采购单回到待结算，按流程三走。
  2. 一张采购单同一时间只能在一张未办结的采购结算单内（沿用防重复纳入校验）。
  3. 结算单确认后金额锁定，付款按发货前应付与尾款分期登记。

6.3 后台代确认

采购 → 采购管理 → 采购结算：按采购结算单展示待确认清单，供后台代合作商确认、登记异议，用于线下已确认的情况。在线确认仍以合作商终端的结算管理为主。

七、财务端页面职责

页面 改动 操作
发票管理 只读台账改为操作页，分销项（待开票）、进项（待收票）两个页签 开票登记（已确认的销售结算单）、收票登记（已确认的采购结算单）
收款管理 只读台账改为操作页，分待回款、回款记录、预存账户 收款登记、预收款登记、手工办结（已收款但无需开票的客户）
付款管理 只读台账改为操作页，分待付款（含待预付）、付款记录 付款登记、手工办结（已付款但无需收票的供应商）
应收管理、应付管理 保持只读台账 点击行就地打开结算单详情
财务概览 新增结算待办卡：待对账履约单、待确认结算单、待开票、待收票、待回款、待付款 角标用已确认的右上角红色数字样式（订单管理页比单管理 / 退货管理按钮的实装样式）
对账结算分组（合作商结算、客户对账） 删除 生成与确认迁到销售、采购菜单；收票与付款迁到发票管理、付款管理

财务侧两条规则：

  • 只能对已确认的结算单登记开票与收付（现行校验保留）。
  • 结算单详情抽屉做成共享组件：销售结算、采购结算和财务各页打开的是同一个详情，按钮按角色显示（第九节）；财务台账页就地打开，不跳菜单。

九、结算单界面与权限（三项补强）

9.1 阶段显性化

结算单详情抽屉分「对账」「结算」两段，顶部状态条同步分两段：

单据 对账段 结算段
销售结算单 待确认 → 已确认（有异议为分支，显示异议原因） 开票进度（已开票 / 结算净额）、收款进度（已收 / 结算净额）→ 已办结
采购结算单 · 签收后付款 待确认 → 已确认（有异议为分支） 收票进度、付款进度 → 已办结
采购结算单 · 先款后货 待确认 → 已确认（有异议为分支） 待预付 → 已预付 → 已签收，其后收票进度与尾款进度 → 已办结
  • 三个时间点显示在状态条上：生成、确认、办结；每次操作记入单据的操作记录（操作人、时间、动作、金额）。
  • 结算单列表增加「阶段」列：对账中、结算中、已办结，按 2.2 的规则派生。
  • 履约单和采购单同步显示结算阶段：待对账、对账中、结算中、已办结。订单进度里的「结算中」是后三者的上位状态，确收即进入。
  • 「对账」段放明细行、异议、调整与冲减、确认信息；「结算」段放发票与收付记录、办结信息。

附录 A：对账单与结算单是否分立的分析

问题：采购和销售是否需要分别生成对账单和结算单，即采购对账单、采购结算单、销售对账单、销售结算单四张单据。

结论：不需要。维持两单制，销售、采购各一张结算单，对账与结算作为单据内的两个阶段（见 2.2）。

判断要点：

判定点 两单制 四单制 分析
金额口径传递 单内延续，没有传递 对账单的确认金额传给结算单，需要一致性校验 四单制多一层映射；销平台实价与扣点快照已随单固化，拆分没有增量收益
操作者与权限 同一张单据按阶段分工 各自操作各自的单据 权限分段（见 9.2）之后边界同样清晰
先款后货 发货前创建，一张单走完 预付发生在对账之前，没有可对账的交割明细 四单制要再造预付款单，或允许没有对账单的结算单
操作负担 每次结算一张单 每次结算两张单，预付场景三张 结算单是手工生成，没有周期结转需求，多出的一步转结算单是重复操作

场景压测：

场景 结论
月结合作商，多张采购单 对账单与结算单的明细完全相同，转结算单是重复操作
一张结算单分三次收款 单内多笔登记已支持，拆分没有收益
先款后货，定金加尾款 两单制一张单走完；四单制需要预付款单
客户来账 登记来账后同一张单继续开票收款
退货冲减 两单制只冲减一张单；四单制两张单都要冲减
审计追溯 用阶段显示、时间点、操作记录补足（见 9.1）

今后出现以下任一情况时再评估拆分：

触发条件 原因
对账确认与付款审批分设审批人，各有一条审批流 单内阶段无法承载两级审批链
一张结算单开票给不同主体 结算主体与对账主体分离，必须拆单
合作商要求按采购单逐单结算并匹配银行流水 粒度下沉到采购单
客户采买平台上线在线对账，签认单据需要独立存档编号 平台侧对账单需要与后台分离

届时可在结算单确认环节引用其明细生成下一张单据，历史数据不受影响。
