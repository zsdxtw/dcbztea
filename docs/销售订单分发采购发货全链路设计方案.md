# 销售订单分发 · 采购 · 发货全链路设计方案

> 基于 2026-10 订单分发模块现状(三环节:订单录入/分发/发货/结算)的纵深设计。
> 方案对标主流 OMS/ERP 的三单分离模型(SO 销售单 / PO 采购单 / 包裹发货单)+ Drop-Shipping 直发模式 + ATP 净需求计算。
> 文档定位:总体设计与实施路线;阶段①(PO 实体化)+ 阶段②(合作商发货闭环,含行内多次发货)已于 2026-10-26 落地开发,阶段③④待实施。

---

## 一、业务背景与问题

销售订单来源:联机推送 / 手工创建。进入后做分发处理:

- **自营**:平台自己采购发货;
- **转派(分发)**:分发给合作合作商,四种方式——
  1. **指定**:直接指定某合作商;
  2. **报备**:与合作商此前在终端报备的商机自动匹配,命中先自动匹配,防止被分发给别的合作商;
  3. **抢单**:发布后先到先得;
  4. **比单**:发布后各合作商报名,按价格与日常合作积分的权重评分,最高者得。

待解决的设计问题:

| # | 问题 |
|---|------|
| A | 分发给不同合作商需要**拆单**,拆单后在管理后台怎么展示 |
| B | **自营订单的发货管理** |
| C | **所有销售订单的管理**(含合作商拿到订单的发货进展) |
| D | 自营采购两类:**以销定采** / **库存发货**(不采购、部分采购、多合作商采购) |
| E | 合作商订单=向合作商采购:**自动生成采购单**、合作商终端**拆单发货**、物流信息**同时关联采购单与销售订单** |
| F | 采购、销售一级菜单设置与职责划分 |

## 二、领域模型:三单分离 + 三级关联键(地基)

```
联机推送 / 手工创建
      ↓
【SO 销售订单·母单】WB…(客户需求事实源:客户/销售实价/应收)
      ↓ 订单分发(报备自动匹配 → 指定/抢单/比单/自营)+ 按供应商拆分
【SO 子单】WB…-1 / -2(供应分片:供应方式=自营|转派、供应主体)
      ├─ 自营子单 → 供应方案(ATP 净需求)→ ①库存直发 ②生成 1..N 张 PO
      └─ 转派子单(=向合作商采购)→ 自动生成 1 张 PO(直送 Drop-Shipment)
      ↓
【PO 采购订单】CG-WB…-1(供应商/采购实价/关联子单/配送方式:直送|入库)
      ↓ 发货(合作商可分批 = 行内多次发货)
【PKG 包裹/发货单】(物流公司+单号+商品行;外键同时挂 PO + 子单 + 母单)
      ↓ 签收 → 结算(转派 PO=应付,母单=应收)
```

**核心规则**:

- 转派子单与 PO **1:1**(子单供应商唯一,定案即自动生成 PO);
- 自营子单与 PO **1:N**(可从多个合作商采购)+ 可选库存直发(0 张 PO);
- **包裹是物流信息的唯一挂载点**,通过 `poId + childOrderId + motherOrderId` 三键,天然实现「物流同时关联采购单和销售单」——任何一端看物流都是同一份数据透传。

## 四、自营发货管理与两类采购(B+D,核心)

自营四态(以销定采 / 纯库存 / 部分采购 / 多源采购)本质是同一个问题:**ATP 净需求计算**。设计「**供应方案**」挂在自营子单上:

```
自营子单 → 供应方案(逐商品行)
  净需求 = 订单数量 − 可用库存(现存量 − 已预留量)
  净需求 = 0  → 【库存发货】→ 生成销售出库单(不生成 PO)
  净需求 > 0 → 【需采购】→ 选 1..N 个供应商(按采购价规则+积分推荐)
              → 按供应商分组生成 PO
```

| 场景 | 净需求结果 | 生成 |
|---|---|---|
| D1 以销定采(单源) | 全部行>0,选 1 家 | 1 张 PO + 入库 + 出库 |
| D2 纯库存发货 | 全部行=0 | 仅出库单 |
| D2 部分采购 | 部分行/数量=0 | 出库单(库存)+ PO(缺口) |
| D2 多供应商采购 | 拆多源 | N 张 PO |

**配套决策**:库存预留(防超卖,预留失败降级采购);发货时机策略默认**齐套发**(全部 PO 到货后一次出库),可选手动分批发;多子单同商品缺口可**合并采购**(采购需求池);发货管理页展示供应方案行状态(待采购→采购中→部分到货→齐套→已出库→已妥投)。

## 五、合作商订单=向合作商采购 + 行内多次发货 + 物流三关联(E)

### 5.1 PO 自动生成

- **时机**:转派定案瞬间(报备确认/指定/抢单定案/比单定标/分拆定案);
- **内容**:供应商=合作商、商品行=子单行、采购价口径(比单=中单价按行金额占比分摊、其余按供应商采购价规则,缺省销售实价 55%)、**配送方式=直送**(免入库)、三键关联;
- **状态驱动**(由订单分发侧动作联动):接单→已确认;结算→已结算;发货在终端登记。

### 5.2 行内多次发货(合作商终端拆单发货)

**数据模型**:

```
PO 商品行:quantity(采购量) / shippedQty(累计已发) / 剩余=quantity−shippedQty
包裹(每次发货登记一条):
  packageNo(PKG-CG-xxx-01/02…) / logisticsCompany / trackingNo / shippedAt
  items: [{ productId, qty }]   ← 本包裹本次发货数量
  status: shipped → delivered(未签收可修改单号/作废,void 回退 shippedQty)
```

示例:某商品 quantity=50,第一批发 30(PKG-01,顺丰)、第二批发 20(PKG-02,德邦)——行 shippedQty 30→50,PO 状态 部分发货→全部发货。

**发货登记交互(合作商终端)**:PO 详情 → 发货登记表单,每个未发完商品行一个数量输入(默认=剩余全部,可改小)+ 物流公司/单号 → 提交生成包裹;未发完可继续登记,同一商品可发 N 批;发货台账展示全部包裹(未签收可改单号、可作废)。

**校验规则**:本次数量 >0 且 ≤ 剩余(防超发);至少一行 >0 才可提交;全部发完后不可再登记(先作废);已签收包裹不可作废(走退货)。

**状态推导**:

| 事件 | 行状态 | PO 状态 |
|---|---|---|
| 合作商接单 | 未发 | 已确认 |
| 第 1 批发 30 | 部分发货 | 部分发货 |
| 第 2 批发 20 | 已发完 | 全部发货 |
| 作废 PKG-02 | 部分发货(回退) | 部分发货 |

### 5.3 物流信息三重关联

- 包裹字段 + 三键(`poId / childOrderId / motherOrderId`);
- **合作商终端**:发货台账;**采购订单页**:PO 详情包裹时间线(多批逐条、行级 x/y 进度);**销售侧**(订单发货页/子单详情/母单总览):同一包裹数据透传(N 个包裹 · M 已签收 · 最近单号),**子单妥投判定=全部包裹已签收**;**客户视角**:只看物流轨迹。

## 六、所有销售订单的管理(C)

订单发货页为全渠道视图:母单聚合下钻三层(子单状态 → PO 进度 → 包裹物流);异常看板(超时未接单/超时未发货/物流停滞);妥投确认(逐包裹或一键全部签收)→ 进入订单结算环节。

## 七、菜单设计(F)

**销售模块**:

| 菜单 | 定位与动作 |
|---|---|
| 销售概览 | 驾驶舱(三环节漏斗+异常) |
| 订单录入 | 手工创建 SO |
| 订单分发 | 分发工作台:报备自动匹配、指定/抢单/比单/自营、拆单、重新分发、母子展示 |
| 订单发货 | 全渠道发货:自营供应方案执行、转派 PO 进度、包裹物流卡、妥投确认 |
| 订单结算 | 待结算→已结算、按时/超时积分 |
| 销售订单 | 订单台账:全部 SO 只读档案+查询导出+母单报表 |
| 比单管理 | 比单会话、评分定标、直接选定 |
| 客户管理 / 下单账号 / 客户对账 / 销售退货 | 维持现状 |

**采购模块**:

| 菜单 | 定位与动作 |
|---|---|
| 采购概览 | 驾驶舱 |
| 采购订单 | 全部 PO 统一台账:手工+转派自动+自营自动;状态机;行级发货进度与包裹时间线;入库触发 |
| 采购需求(新增,阶段③) | 自营净需求池:待生成 PO 的需求行,支持合并生成(跨子单同商品并单)与供应商分组 |
| 入库管理 | 自营 PO 到货入库(部分到货支持) |
| 采购报(调)价 | 采购价规则维护(PO 取价源) |
| 合作商管理(注册审批/列表/门店/积分/报备) | 维持现状 |
| 供应商对账 | 按 PO 汇总应付对账(转派 PO=合作商应付单) |

**合作商终端**:订单管理(接单→**发货登记**(行内多次发货+物流填写)→签收)、发货台账。

## 八、关键状态机

- **PO(直送制)**:待确认 → 已确认 → 部分发货 → 全部发货 → 已签收 → 已结算
- **PO(入库制)**:待确认 → 已确认 → 部分到货 → 齐套 → 已入库 → 已结算
- **包裹**:已发货 → 已签收(未签收可作废)
- **母单**:待分发 → 分发中 → 部分履约 → 全部妥投 → 已结算 → 完成
