# 合作商工作台订单管理设计评审

- 版本：v1.0
- 日期：2026-11-22
- 范围：合作商工作台（`/partner`）「订单管理」页面及其关联弹窗、数据来源、与管理后台的口径一致性
- 目的：梳理订单管理的页面结构与数据链路，识别设计与实现问题，给出目标态与优化优先级

---

## 一、定位与菜单

合作商工作台是独立终端（`src/pages/partner/PartnerLayout.tsx`），侧边菜单为：

| 菜单 | 路径 | 适用对象 |
|---|---|---|
| 工作台 | `/partner/dashboard` | 全部 |
| 客户池 | `/partner/customers` | 全部 |
| **订单管理** | `/partner/orders` | 全部 |
| 报备管理 | `/partner/reports` | 服务商 |
| 业务推介 | `/partner/referrals` | 全部 |
| 供货报价 | `/partner/quotes` | 供应商 |
| 结算管理 | `/partner/settlement` | 全部 |
| 积分管理 | `/partner/scores` | 全部 |
| 设置 | `/partner/account` 等 | 全部 |

订单管理承接三类来源：指定转入、报备转入（含商机报备）、比单转入，是合作商履约的主入口。

## 二、页面结构

页面文件：`src/pages/partner/PartnerOrders.tsx`。

| 区块 | 内容 |
|---|---|
| 状态 Tab | 全部 / 待接单 / 已接单 / 已发货 / 已确收 / 已结算 / 已取消，均带单数；「已发货」合并「发货中 + 妥投」 |
| 筛选 | 关键词（编号 / 客户 / 收货人）、配送方式（直送 / 入仓）、合作模式（差价 / 扣点）、客户、收件省市县三联、下单日期区间 |
| 工具栏 | 比单管理（角标 = 参与中比单数）、退货管理（角标 = 处理中退货数） |
| 表格 | 15 列：序号、销售单编号、销售路径、客户、总金额、收件人 / 电话 / 地区、配送方式、合作模式、来源类型、状态、下单日期、操作 |
| 详情抽屉 | 订单信息、履约五节点时间线、商品明细、发货台账（包裹级）、收货信息 |
| 弹窗 | 接单确认、整单退回、发货、比单报名、比单管理、退货管理 |

### 2.1 行内操作（按状态）

| 状态 | 行内操作 | 说明 |
|---|---|---|
| 待接单（普通） | 接单、退回（仅分发链订单）、查看 | 接单需弹窗确认并展示商品明细 |
| 待接单（比单） | 报名 / 查看报名、查看 | 已报名展示「已报名 + 报价」 |
| 已接单 | 发货、查看 | 发货支持自行配送 / 物流公司与按商品拆批 |
| 已发货 | 确认妥投、查看 | 推进后进入 `transit` |
| 已妥投 | 仅查看 | 提示「待管理后台确认收货」 |
| 商机报备订单 | 无操作 | 平台履约，仅同步展示 |

### 2.2 详情抽屉内容

- 订单信息：编号、客户与类型、配送方式、合作模式、来源类型、状态、下单日期、预计发货、总金额、比单底价、转入来源；
- 履约时间线：来单 / 接单 / 发货 / 妥投 / 确收五节点（仅平台流转订单）；
- 商品明细：名称、规格、数量、单价、小计；
- 发货台账：包裹号、物流公司 / 单号、本次发货、发货时间、状态；
- 收货信息：收货人、电话、地址、备注。

## 三、数据来源与状态映射

### 3.1 三源拼接

页面数据由三份合并而成：

| 来源 | 生成方式 | 状态存放 |
|---|---|---|
| 分发链订单 | `getPartnerFlowOrders()` 从 `orderFlowStore` 投影 | store（持久） |
| 报备转入订单 | `getTransferredOrders(reports)` | 组件 `useState`（会话级） |
| 静态演示订单 | `src/data/partner` 的 `partnerOrders` | 组件 `useState`（会话级） |

### 3.2 状态映射

| 合作商侧 `PartnerOrderStatus` | 平台侧 `processStatus` / `fulfillment.stage` |
|---|---|
| `pending` | `distribute_pending` 或比单中订单 |
| `accepted` | `processed` + `stage=accepted`（比单中单未写 partnerStatus 时直接视为已接单） |
| `shipping` | `processed` + `stage=shipping` |
| `transit` | `processed` + `stage=transit` |
| `confirmed` | `processed` + `stage=confirmed` |
| `cancelled` | `processStatus=cancelled` |

### 3.3 状态 Tab 口径

- 「已发货」Tab = `shipping` + `transit` 合并；
- 「已结算」Tab 取的是 `settled` 标记，不是履约状态；
- 比单订单在未定标前以 `pending` 混在「待接单」中，通过 `compareSigned` 区分展示。

## 四、问题与优化建议

### 4.1 P0：数据一致性与流程阻断

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 三源拼接，其中两源状态存组件 `useState`（`transferOverrides`、`manualOrders`） | 刷新 / 切页即丢失；工作台、结算、积分页与订单页口径不一致 | 收敛为统一的 partner 订单投影 store，页面只读；静态种子移出生产路径 |
| 2 | `getPartnerFlowOrders` 中 `deliveryMode` 固定 `'direct'`、`coopMode` 固定 `'supplier'` | 服务商订单被显示成「差价模式」，入仓单被显示成「直送」，两个筛选失真 | 由合作商档案的合作模式与订单实际履约方式推导 |
| 3 | 双状态真源：`partnerStatus` 与 `fulfillment.stage` 镜像写 | 出现「分发已完成但履约未接单」等矛盾 | 确立 `fulfillment.stage` 为单真源，`partnerStatus` 仅派生只读 |
| 4 | 无采购单关联的发货直接置「已发货」且不落物流；「自行配送」写入假单号「自送无单号」 | 发货凭证与物流追溯缺失，平台侧无法查看包裹台账 | 无单据也强制生成包裹记录（可自送、无单号但需留痕），禁止假单号进入物流字段 |
| 5 | 一次发货只能填一个物流公司 + 一个单号 | 与管理后台包裹级设计冲突，无法一单多包 | 发货弹窗支持多包裹行（每包商品 + 数量 + 单号） |
| 6 | 退货走 `returnStore`，平台「销售退货」页却是静态数据 | 平台端看不到合作商退货，退货无法回写订单与结算 | 以 `returnStore` 为唯一真源，销售退货页消费它 |

### 4.2 P1：流程闭环与权限

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 接单不采集「承诺发货时间 / 备货周期」 | 平台无法做时效考核，超时无依据 | 接单弹窗增加承诺发货日期，写入履约时间线 |
| 2 | 退回不要求填写原因、无次数限制、无责任归属，且仅分发链订单可退 | 退回滥用，责任不可追溯 | 退回必填原因；限制次数；记录操作人与时间 |
| 3 | 接单后无法申请取消或转回 | 合作商无法履约时只能硬扛或线下沟通 | 增加「申请取消 / 申请转回」经平台确认 |
| 4 | 管理后台可直接推进合作商链的发货 / 妥投 / 确认收货 / 结算 | 与「动作由执行端产生」规则冲突 | 仅保留代操作并打审计标记，或限定异常兜底权限 |
| 5 | 比单入口弱化：可报名订单混在「待接单」，无独立比单大厅 | 合作商容易错过报名窗口 | 增加比单大厅或在待接单内分区，展示地区范围、截止倒计时、我的报价排名 |
| 6 | 比单管理角标只统计已报名的进行中订单 | 未报名但可参与的比单无提示 | 角标拆分「可报名 / 已报名」，并做临近截止提醒 |
| 7 | 合作商只能看到客户售价 `totalAmount`，看不到自己的结算金额 | 差价模式不知毛利、扣点模式不知扣点后金额 | 详情增加「结算信息」区：合作模式、扣点率或采购价、预计结算金额、结算单号 |
| 8 | 认证兜底为空时静默显示空列表 | 用户以为没有订单 | 明确提示「账号未绑定合作商档案」并给出处理入口 |
| 9 | 客户电话与完整地址直接展示 | 隐私风险 | 按角色脱敏，完整信息进入详情留痕 |

### 4.3 P2：列表体验

| # | 问题 | 建议 |
|---|---|---|
| 1 | 15 列 + `minWidth: 1200` 强制横向滚动 | 精简列为「编号 / 客户 / 金额 / 状态 / 时效 / 操作」，其余进详情或列配置 |
| 2 | 无排序、无导出、无列设置、无批量发货 | 补排序（截止时间 / 金额 / 下单日期）、导出、列设置、批量发货 |
| 3 | 搜索仅支持编号 / 客户 / 收货人 | 扩展商品名、物流单号、报备编号 |
| 4 | `expectedShipDate` 以录入时间兜底 | 无实际意义，应取承诺发货时间；无值时显示 `—` |
| 5 | 「已结算」作为状态 Tab 与其他状态不同维度 | 移为独立筛选，或作为行内第二个标签 |
| 6 | 状态药丸过多（销售路径、配送方式、合作模式、来源类型、状态） | 合并次要标签，仅保留状态与来源为主视觉 |

### 4.4 与管理后台的口径一致性

| 维度 | 管理后台 | 合作商工作台 | 建议 |
|---|---|---|---|
| 发货执行 | 不提供发货录入，仅查看包裹台账并推进妥投 / 确收 | 发货主入口：自行配送或物流公司 + 单号，支持按商品拆批 | 保持双端分工：合作商与自营工作台负责发货，管理后台只做查看与异常兜底 |
| 发货态命名 | 已发货 / 已妥投 | 已发货（含妥投） | 统一为「已发货（运输中 / 已妥投）」双层展示 |
| 确收主体 | 管理后台「确认收货」 | 合作商显示「已确收」 | 明确合作商侧只到「已妥投」，确收由平台写入后展示 |
| 状态词表 | `pending_accept/accepted/shipping/transit/confirmed` | `pending/accepted/shipping/transit/confirmed` | 建立映射字典，禁止各页自造文案 |
| 时间口径 | 履约五节点 | 五节点（仅流转订单） | 演示订单也应有时间或显示 `—` |

## 五、目标态设计建议

### 5.1 列表

- 状态分区：待接单（含「可报名比单」子区）、待发货、运输中、已妥投、已完成（待结算 / 已结算）、已取消；
- 主列：销售单编号、客户、金额、时效（接单截止 / 承诺发货 / 已超时）、状态、操作；
- 行内主操作只保留当前状态唯一主动作（接单 / 发货 / 确认妥投 / 报名），其余进详情；
- 超时行高亮，并在 Tab 上显示超时数量。

### 5.2 详情抽屉

在现有内容上补充：

- 结算信息：合作模式、扣点 / 采购价、预计结算金额、结算状态与结算单号；
- 时效信息：来单时间、接单时限、承诺发货时间、实际发货时间、超时标记；
- 操作轨迹：与合作商相关的全部动作与操作人；
- 关联单据：采购单 / 包裹 / 退货单 / 结算单的可跳转链接。

### 5.3 发货

- 支持一单多包裹，每包独立物流公司与单号；
- 自行配送必须填写送达时间或签收凭证，不写假单号；
- 展示发货进度（已发 / 剩余），支持继续发货；
- 无采购单关联时也生成包裹记录，保持与管理后台包裹台账、自营工作台发货同源。

### 5.4 比单

- 独立比单大厅或明确分区，展示：订单摘要、地区范围、底价、截止倒计时、当前报名数、我的报价与排名；
- 报名后可在列表看到「比单中」标记与截止提醒；
- 未中单结果明确展示，不留在待接单里。

### 5.5 退回与取消

- 退回必填原因、限制次数、记录责任；
- 已接单后提供「申请取消 / 申请转回」，由平台审批并留痕。

## 六、实施优先级

| 优先级 | 事项 |
|---|---|
| P0 | 合作商订单全量入 store；修复 `coopMode` / `deliveryMode` 硬编码；单真源；发货留痕与多包裹；退货统一 `returnStore` |
| P1 | 接单承诺时效、退回原因与次数、申请取消、比单大厅、结算信息可见、权限与脱敏 |
| P2 | 列表列精简与排序导出、搜索扩展、状态标签收敛、时间口径统一 |
