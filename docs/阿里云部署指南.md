# 阿里云部署指南（dcbztea 淡茶半盏）

> 项目形态：**纯前端静态应用**（Vite 5 + React 18，无后端、无 API 依赖，演示数据存内存/localStorage）。
> 构建产物：`npm run build` → `dist/`（index.html + 带 hash 的静态资源）。
> 两种推荐方式：**方式一 OSS 静态托管（免服务器，最省）** / **方式二 ECS + Nginx（最通用）**。

---

## 〇、部署前必读

| 事项 | 说明 |
|------|------|
| **SPA 回退必须配置** | 项目使用 BrowserRouter（/sales/xxx 等前端路由），直接刷新子路径会 404，必须让所有路径回退到 `index.html`（Nginx `try_files` / OSS 错误文档） |
| **ICP 备案** | 中国大陆的 OSS/ECS 绑定自定义域名必须完成 ICP 备案（阿里云控制台提交，约 1-2 周）；备案期间可用临时 IP 或免备案的港澳台/海外节点 |
| **HTTPS** | 阿里云「数字证书管理服务」每年可免费申请 20 张 DV 证书；或服务器用 certbot 免费证书 |
| **包体积** | 主 bundle 约 2.3MB（gzip 后约 720KB），务必开启 gzip（Nginx 已配 / CDN 自动） |
| **数据形态** | 当前为演示数据（内存+localStorage），正式对外需后续接入后端（届时 Nginx 增加 `/api` 反代即可，nginx.conf 已留注释） |
| **子路径部署** | 默认部署在域名根路径；若部署到 `https://xx.com/dcbz/` 子路径，需在 `vite.config.ts` 增加 `base: '/dcbz/'` 后重新构建 |

## 方式一：OSS 静态托管（免服务器，推荐演示/低成本）

**适合**：无后端纯静态站，按量付费几乎零成本（存储+流量费）。

### 1. 创建 Bucket
- 控制台 → 对象存储 OSS → 创建 Bucket：华东（杭州）等任意地域
- **读写权限：公共读**（静态站必须）

### 2. 构建并上传
```bash
npm run build
```
- 控制台上传：Bucket → 文件管理 → 上传文件 → 选择 `dist/` 下**所有内容**（注意是 dist 里面的内容，不是 dist 目录本身）
- 或用 ossutil（推荐）：
```bash
# 安装 ossutil 后先配置 AK/SK：ossutil config
ossutil cp -rf dist/ oss://你的bucket名/
```

### 3. 开启静态页面托管 + SPA 回退
- Bucket → 基础设置 → **静态页面**：
  - 默认首页：`index.html`
  - 子目录首页：`index.html`
  - **错误文档（404）：`index.html`** ← 这是 SPA 回退的关键（刷新 /partner/login 等路径不会 404 白页）

### 4. 绑定域名 + HTTPS + CDN（可选）
- Bucket → 传输管理 → 绑定自定义域名（需已备案）；或在域名上直接配置 **CDN 加速**（源站选该 OSS）
- HTTPS：CDN/OSS 域名配置 → HTTPS 证书 → 选择免费 DV 证书（先在「数字证书管理服务」申请并绑定域名）

> OSS 方式注意：错误文档方案返回的状态码是 404（内容为 index.html），演示环境够用；若要求严格 200，可用 CDN 的「回源改写/EdgeScript」把所有路径改写为 /index.html，或改用方式二。

## 方式二：ECS / 轻量应用服务器 + Nginx（通用标准做法）

**适合**：需要完整控制、后续要接后端/数据库的场景。

### 1. 购买服务器
- ECS 或**轻量应用服务器**（新人优惠便宜）：2核2G 起步即可（纯静态站压力极小）
- 操作系统：Ubuntu 22.04 或 Alibaba Cloud Linux
- **安全组/防火墙：放行 80、443、22 端口**

### 2. 安装 Nginx 并初始化目录
```bash
ssh root@服务器IP
# Ubuntu
apt update && apt install -y nginx
# Alibaba Cloud Linux
# yum install -y nginx && systemctl enable --now nginx

mkdir -p /var/www/dcbztea
```

### 3. 上传 Nginx 配置（仓库已备好）
```bash
# 本地执行（或手动复制 deploy/nginx.conf 内容）
scp deploy/nginx.conf root@服务器IP:/etc/nginx/conf.d/dcbztea.conf
# 服务器上把 server_name 改成你的域名或 IP，然后：
nginx -t && nginx -s reload
```
配置要点（已在 `deploy/nginx.conf` 内）：`try_files $uri $uri/ /index.html` SPA 回退、assets 长缓存、index.html 不缓存、gzip。

### 4. 构建并发布
```bash
# 本地执行一键脚本（首次先改脚本里的 SERVER/REMOTE_DIR）
bash deploy/deploy.sh
# 或手动：
npm run build
rsync -avz --delete-after dist/ root@服务器IP:/var/www/dcbztea/
```
浏览器访问 `http://服务器IP` 即可。

### 5. 域名 + HTTPS
- 阿里云「云解析 DNS」：域名添加 A 记录 → 服务器公网 IP（大陆服务器需备案）
- 证书：数字证书管理服务申请免费 DV 证书（Nginx 版）→ 上传 pem/key 到服务器 → 启用 nginx.conf 中注释的 443 配置段 → reload

## 持续部署（可选）

| 方案 | 说明 |
|------|------|
| **手动** | 每次更新：`git pull && npm run build && bash deploy/deploy.sh`（最简单） |
| **GitHub Actions** | push 到 dcbz 分支自动 build，通过 ssh/ossutil 部署（需在仓库 Secrets 配服务器私钥或 OSS AK/SK；注意本机访问 GitHub 网络不稳，服务器侧拉取更稳） |
| **阿里云云效 Flow** | 国内 CI 首选：源→构建（npm ci && npm run build）→部署（ossutil 上传 或 主机组执行 rsync 脚本） |

## 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 首页正常，刷新子路径 404 | SPA 回退未配置：检查 Nginx `try_files` / OSS 错误文档 |
| 更新发版后页面没变 | index.html 被缓存：确认 `location = /index.html` no-cache；用户强制刷新 |
| 白屏 + 控制台资源 404 | 部署到了子路径但未设 vite `base`，或上传的是 dist 目录而非其内容 |
| 域名打不开 | 未备案被拦截（大陆），或安全组未放行 80/443 |
| 包太大加载慢 | 确认 gzip 生效；后续可做路由级代码分割（vite manualChunks） |
