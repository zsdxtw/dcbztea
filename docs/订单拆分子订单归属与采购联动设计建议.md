# 订单拆分:子订单归属与采购联动 · 设计建议

> 基于 2026-10 订单生成&流转模块(拆单/按商品抢单比单/自动分拆)现状的领域建模分析。
> 讨论问题:一张销售订单按自营/合作商供货逻辑拆分成子订单后,母子订单应放在销售菜单、采购菜单,还是其他处理方式。
> 文档定位:设计建议与落地方案,供决策参考,不涉及代码改动。

---

## 一、问题本质

当前拆单产生的子订单,是一种**混合体**:

| 视角 | 子订单承载的信息 | 归属倾向 |
|------|------------------|----------|
| 销售视角 | 客户、收货地址、销售实价、订单金额——它是销售订单的一个"履约分片" | 销售 |
| 采购视角 | "这批商品向合作商 X 采购"——供货来源、供货商唯一 | 采购 |
| 履约视角 | 合作商直送客户(接单→发货→签收),不走入库 | 既不是纯采购入库,也不是纯销售发货 |

关键判断:**子订单本身不是"采购订单"**。本项目语境下采购订单 = 淡茶半盏 → 合作商、以**采购实价**结算、伴随**入库**的单据;而分发子订单以**销售实价**面向客户、**直送不入库**、由合作商向客户履约。它更像 ERP 里 SO→PO 转单中的「供货指令 / 履约分配」。

因此"把子订单整体搬到采购菜单"会造成两个域的数据模型错位:采购页要展示客户地址?销售页丢失分片状态?两头别扭。

---

## 二、方案对比

| 方案 | 做法 | 评价 |
|------|------|------|
| A. 母子都在销售(现状) | 订单生成&流转内闭环 | ✅ 流转状态机/抢单比单/重新流转不打断;❌ 采购域完全看不见"向合作商分了什么",采购订单页与流转世界两张皮(优化文档 P0 断点的延续) |
| B. 母在销售、子在采购 | 子订单移入采购菜单 | ❌ 不推荐:采购订单模型(采购实价+入库)套不上直送子订单;合作商终端履约动作、母子 Tab、抢单比单状态机都会被切断;报表口径混乱 |
| **C. 母子留在销售 + 子单向采购域投影「采购委托单」(推荐)** | 销售域保持母子族完整事实;每个已定方向的子订单在**采购菜单生成一张采购侧单据** | ✅ 各归其位:销售管"卖给谁、卖多少",采购管"向谁买、买多少";两域通过单据关联而非搬家 |

## 三、推荐方案(C)设计

### 3.1 单据模型

```
销售域(订单生成&流转)                  采购域(采购 → 采购订单)
┌ 母订单 WB20261025001(流转-待处理)
│   ├ 拆单/分拆定案
│   ├─ 子订单 -1(分发-抢单→云茶) ──投影──▶ 采购委托单 CG-WB…-1(供应商=云茶, 直送, 采购价=报价口径)
│   ├─ 子订单 -2(分发-比单→八马) ──投影──▶ 采购委托单 CG-WB…-2(供应商=八马, 直送, 采购价=中单价)
│   └─ 子订单 -3(转自营) ─────────────▶  自营采购单 WB-CG-xxx(已有 selfChain, 补入采购订单列表)
└ 未成子单(抢单/比单未成)留在销售继续流转, 不生成采购单
```

- **销售域**:母子订单族 + 状态机 + 拆单/重新流转 + 详情母子 Tab(现状保留)。
- **采购域**:新增「流转采购」单据(采购委托单),字段 = 关联销售子订单号、供应商、商品数量、**采购口径金额**(自营=采购实价;比单=中单价×数量;抢单=报价;指定=合作商报价)、配送方式(直送/自营入库)、状态(待接单/已接单/已发货/已签收/已结算)。**不复制客户销售价**,避免报表双算。

### 3.2 生成时机与状态同步

1. **生成**:子订单定案瞬间——分发转出(指定/报备确认/抢单定案/比单定标)时自动生成对应采购委托单;自营接单时生成采购单(现有 selfChain 机制)。
2. **同步**:以 orderFlowStore 为**唯一事实源**,采购侧单据随子订单状态自动推进(接单→发货→签收→结算),采购页只读展示或做轻量引用——**不做双向写**,避免状态分叉。
3. **作废**:子订单「重新流转」时,对应采购委托单自动作废/红冲,并在处理轨迹留痕。

### 3.3 菜单与权限职责

| 菜单 | 职责 | 看到什么 |
|------|------|----------|
| 销售 → 订单生成&流转 | 需求与分配 | 母子订单族全貌、流转状态、拆单 |
| 采购 → 采购订单(新增「流转采购」Tab) | 向合作商买什么 | 手工采购单 + 流转生成的采购委托单/自营采购单,来源标签区分 |
| 合作商终端 | 履约 | 仅自己名下的子订单(现状不变) |
| 财务/对账 | 供需两头 | 应收(销售实价,按母订单)与应付(采购口径,按采购委托单)分开核算 |

### 3.4 金额口径(必须显式定义)

- 母订单金额 = Σ 销售实价(**应收口径**);
- 采购委托单金额 = **采购口径**(供应商报价 / 比单中单价 / 抢单价),**不用销售实价**;
- 毛利 = 母订单应收 − Σ 采购委托单应付——这也是后续平台分账/绩效规则得以成立的地基。

## 四、分阶段落地方式

| 阶段 | 内容 | 成本 |
|------|------|------|
| 阶段一(纯投影) | 采购订单页新增「流转采购」Tab,直接从 orderFlowStore 派生:自营子单(selfChain)+ 已分发子单(合作商),按 3.1 字段展示,状态只读联动。零数据复制 | 一天量级 |
| 阶段二(正式单据) | 转出/接单时写入 purchaseStore 生成正式采购委托单(带采购实价取价:优先该供应商报价规则),打通:直送单免入库、自营单联动入库、供应商对账按月汇总委托单、财务应付联动(对应优化文档 P0-2/P0-3) | 中 |
| 阶段三(可选) | 母订单台账化——分拆定案后母订单不删除而转为"分配完成"的容器单,可随时看整单完成度(各子单进度/未成余量回流),报表按母单归集收入 | 中 |

## 五、端到端流程(目标态)

```
外部订单进入 → 保存即匹配报备(待确认)
  → 流转弹窗选路径(转自营 / 分发-指定·报备·抢单·比单)
  → 抢单/比单按商品定案
  → 分拆生成子订单(销售域母子族)
  → 每个定向子单自动生成采购委托单(采购域)
  → 合作商接单直送客户 / 自营采购入库出库
  → 客户签收
  → 结算(应付按委托单、应收按母订单、履约 ±积分)
  → 全部子单闭环后母订单完成
```

## 六、边界与注意点

1. **报表口径**:收入按母订单(销售实价)、成本按采购委托单(采购口径)分别归集,子订单不得在两域重复计数。
2. **母订单台账**:当前自动分拆会移除母订单,若需整单完成度视图,按阶段三台账化处理,与手动拆单(母单保留)口径统一。
3. **直送与入库差异**:分发子单=直送免入库;自营子单=入库+出库。采购委托单需带配送方式字段,仓储联动仅作用于自营。
4. **权限**:采购员只见采购投影(供应商、商品、采购价),不见客户销售价;销售侧与终端按现状。
5. **重新流转联动**:凡产生过采购单据的子订单重新流转,必须级联作废采购委托单并留痕,防止"两边各说各话"。

---

## 七、结论

**母子订单都留在销售菜单**(它是销售订单的履约分片,事实源不动);"子订单是采购维度"的诉求,通过**在采购菜单生成/投影对应的采购委托单**来满足——销售管需求与分配,采购管供应与成本,两域用单据关联,而不是把订单在菜单间搬家。
