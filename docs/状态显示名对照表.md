# 状态显示名对照表（销售单状态 / 履约单状态分开）

> 口径来源：`src/utils/salesOrderFamily.ts`（`distributeStateOf` / `fulfillStateOf` / `receiveStateOf` / `invoiceStateOf` / `settleStateOf` / `orderProgressOf` / `familyStatesOf`）、`src/utils/fulfillment.ts`、`src/data/externalOrders.ts`。
> 状态体系：**销售单**只保留订单状态（处理中 / 已办结 / 已取消）+ 三个进度聚合；**履约单**分四块：分发状态、履约状态、结算状态（收款·开票二维组合）、订单进度。

---

## 一、销售单（母销售单）

### 1.1 订单状态（4 态）

| 枚举值 | 定义 | 显示名 |
|---|---|---|
| 未处理 | 销售单刚进入平台，尚未送分发、未生成履约单（未确定拆成几个履约单） | **未处理** |
| 处理中 | 已送分发/已生成履约单，存在未办结且未取消的履约单 | **处理中** |
| 已办结 | 其下全部履约单均已办结 | **已办结** |
| 已取消 | 其下全部履约单均已取消（或未处理即被取消） | **已取消** |

### 1.2 三个进度聚合（按履约单维度，x/y 分母为有效履约单数，剔除已取消）

| 进度 | 档位 | 判定 |
|---|---|---|
| 分发进度 | 未分发 / 分发中 / 分发完成 / 已取消 | 分发已完成履约单数 / 有效履约单数 |
| 履约进度 | 未履约 / 履约中 / 履约完成 / 已取消 | 已确收履约单数 / 有效履约单数 |
| 结算进度 | 未结算 / 结算中 / 结算完成 | 已收款履约单数 / 有效履约单数 |

---

## 二、履约单状态（四块）

### 2.1 分发状态（`processStatus` · 5 态）

| 枚举值 | 显示名 |
|---|---|
| `pending` | 待分发 |
| `self_pending` | 自营待接单 |
| `comparing` | 分发比单中 |
| `distribute_pending` | 转派待接单 |
| `processed` | 分发已完成 |

> `unprocessed`（销售单未送分发）与 `cancelled` 不在履约单分发状态中展示（分别由「销售单处理」与「订单进度」承载）。履约状态进入已接单及后续时，分发状态自动置为「分发已完成」。

### 2.2 履约状态（`fulfillment.stage` · 5 态）

| 枚举值 | 显示名 |
|---|---|
| `pending_accept` | 待接单 |
| `accepted` | 已接单 |
| `shipping` | 运输中 |
| `transit` | 已妥投 |
| `confirmed` | 已确收 |

> 未进入履约主体（未分发 / 待分发 / 分发比单中）显示「—」；已取消不在此展示（见订单进度）。

### 2.3 结算状态（收款 + 开票二维组合）

两个维度相互独立，组合展示为一个药丸：

| 收款（`settled`） | 开票（`invoiceStatus`） | 结算状态显示 |
|---|---|---|
| 未收款 | 未开票 | 未收款·未开票 |
| 未收款 | 已开票 | 未收款·已开票 |
| 已收款 | 未开票 | 已收款·未开票 |
| 已收款 | 已开票 | 已收款·已开票 |

- 收款：按发货单（包裹）结算粒度落库，全部已妥投/已确收发货单收款或订单级收款 → 已收款。
- 开票：`uninvoiced`（缺省）/ `partial` / `invoiced`，后两者均显示「已开票」（二元口径）。

### 2.4 订单进度（履约单维度 · 5 态）

| 枚举值 | 判定 |
|---|---|
| 分发中 | 分发状态 ∈ 待分发 / 分发比单中 / 自营待接单 / 转派待接单 |
| 履约中 | 已进入履约（已接单 / 运输中 / 已妥投 / 已确收），且未发起结算、未办结 |
| 结算中 | 已确收且已发起对账结算（`settlementStarted`），尚未办结 |
| 已办结 | 已收款 + 已开票；或已收款后手工办结（`closed`） |
| 已取消 | 订单取消（`processStatus=cancelled`）；分发 / 履约状态不再展示已取消 |

判定优先级：已取消 → 已办结 → 结算中 → 分发中 → 履约中。

---

## 三、结算操作与入口（新增「履约单结算」菜单）

菜单：**销售 → 销售单管理 → 履约单结算**（`/sales/sales-settlement`）

| 操作 | 前置条件 | 结果 |
|---|---|---|
| 发起对账结算 | 履约状态＝已确收 | 订单进度 → 结算中 |
| 登记收款 | 已确收 | 收款维度 → 已收款（按发货单结算落库） |
| 登记开票 | 已确收 | 开票维度 → 已开票 |
| 手工办结 | 已收款且未开票 | 订单进度 → 已办结 |

> 收款 + 开票均完成时订单进度自动变为已办结；手工办结用于「已收款未开票」的业务场景。

---

## 四、贯穿与联动

- **已取消**：仅体现在订单进度；取消逆向为比单中清 compare 会话、在途包裹提示召回、拆分家族母单禁止直接取消。
- **母单/子单**：母销售单只做聚合展示（订单状态 + 3 个进度），具体状态由各履约单承载；未拆分的母销售单即默认履约单 LY01。
- **三端一致**：管理后台、合作商工作台、自营工作台共用 `fulfillment.stage` 履约口径；分发状态与订单进度仅在管理后台展示。
- **旧数据兜底**：无 `fulfillment` 的订单按 `processStatus` / `partnerStatus` 推导履约状态；无 `settled` 但有 `settleOnTime` 的历史数据按已收款兼容。
