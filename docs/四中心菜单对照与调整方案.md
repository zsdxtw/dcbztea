# 四中心菜单对照与调整方案（差距分析）

> 基准：附件《淡茶半盏供应链管理系统设计》（销售中心/采购中心/仓储中心/财务中心 全量设计）× 当前系统（2026-11-02：销售单母子体系、销售单分发、销售单自营、自营工作台、PO 三单分离、四端终端体系已落地）。
> 本文档只做菜单级差距分析与调整设计，不含开发实施。

---

## 一、总体判断

附件的四中心架构与现有系统**高度同构**（销售/采购/仓储/财务 四个一级模块已存在），业务主链路（销售订单 → 履约分配 → 自营/合作商 → 采购 → 发货 → 结算）也已在现有系统跑通。差距不在"框架"，而集中在五处：

| # | 差距领域 | 现状 | 附件要求 |
|---|---------|------|---------|
| 1 | **履约任务显性化** | 以"母子销售单"承载履约（拆单子单=履约载体），管理端无独立履约任务视图 | 独立 FO 履约任务单据：分配/备货/发货/签收数量跟踪、关联 PO 与发货单 |
| 2 | **统一发货管理** | 自营包裹（SelfShipment）+ 采购直发包裹（PO packages）分散在自营工作台/采购页 | 统一"销售发货"菜单：平台仓发货/合作商直发/供应商直发三类发货单 |
| 3 | **库存体系** | 静态演示台账（STOCK_BY_PRODUCT/WAREHOUSE_STOCK），无预留/批次/流水/货权 | 库存总览/明细/预留/流水四层 + 平台与合作商库存分权管理 |
| 4 | **财务应收应付** | 收款/付款为独立 mock 页面，无应收应付账款与核销体系 | AR/AP 账款、收付款核销、三类对账、合作商结算、经营利润 |
| 5 | **采购申请与需求关联** | "采购需求"为缺口只读池；PO 与销售子单单点关联 | 采购申请单据化（四类来源、合并采购保留溯源）+ demand_link 多对多 |

### 概念映射表（附件术语 ↔ 现有实现）

| 附件概念 | 现有实现 | 匹配度 |
|---------|---------|-------|
| 销售订单 SO | 销售单（母单+子单，/sales/sales-orders） | ★★★★（缺审核流、交货日期、结算信息字段） |
| 履约分配 FO-分配 | 销售单分发（自营/指定/报备/抢单/比单 五路径） | ★★★★（缺行内数量级混合分配、可视化分配工作区） |
| 履约任务 FO | 拆单子销售单（分发/自营链执行载体） | ★★★（有实无名的单据载体，缺任务视图与数量六态） |
| 采购申请 | 采购需求（自营缺口只读池） | ★★（非单据、无合并、无四类来源） |
| 采购订单 PO | purchaseStore PO（直发 direct/入库制 warehouse） | ★★★★（缺五类采购类型、直发动态字段组、多销售关联） |
| 采购收货确认 | 入库管理 + receiveByChild（一键入库） | ★★★（缺验收合格/不合格、批次） |
| 采购直发确认 | PO 包裹签收（deliverPackage） | ★★（缺独立确认视图与应付联动） |
| 销售发货单 DO | SelfShipment 包裹 + PO packages | ★★★（两类包裹已有，缺统一发货单菜单） |
| 库存 | 静态台账 + 仓库设置 | ★★（缺预留/明细/流水/货权） |
| 应收/应付 | 销售回款/采购付款（mock） | ★（无账款与核销） |
| 合作商结算 | 销售·订单结算 + 合作商终端结算 | ★★★（缺周期对账单与双方确认流） |

├─ 销售发货（新增）
├─ 比单管理 ｜ 销售报（调）价
├─ 客户管理 ｜ 客户下单账号 ｜ 客户对账 ｜ 销售退货

## 八、三项业务规则确认（附件第十节，结合现状给出建议答案）

## 九、分期实施建议（对齐附件第九节）

- **第一阶段（业务主链路增强，以改造为主）**：销售订单五 Tab 与六态 → 履约分配可视化 → 履约任务菜单（自营=现有销售单自营/自营工作台）→ 销售发货统一菜单 → 采购申请单据化 → 采购收货验收 → 直发确认 → 库存总览/明细/预留/流水基础版 → 应收/应付/收付款
- **第二阶段（供应链完善）**：供应商统一档案与评级、集团客户与授信、调拨两段确认、盘点审核流水、销售/采购退货双向联动、三类对账、合作商结算周期单、经营利润多维
- **第三阶段（智能化）**：自动履约分配、合作商库存同步、智能采购建议、多订单合并采购、履约评分、价格与库存分析（落统计模块）
