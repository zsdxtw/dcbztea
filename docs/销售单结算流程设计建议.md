# 销售单结算流程设计建议（采销分离 · 2026-11-28 全面改版）

> 代码基线：分支 `dcbz`，提交 `50fe6f5`（2026-11-28）。
> 文档沿革：
> - 2026-11-24 初版：客户对账单驱动 + 合作商采购应付联动；其中第七节第 1~4 步已开发落地（`settlementStore.ts` 客户对账单 / 钱包 / 合作商对账单，销售·客户对账、履约单结算、应收 / 收款 / 发票 / 付款 / 合作商结算 / 应付 / 经营利润 / 财务概览接真实数据，退货冲减，积分双门槛）。
> - **2026-11-28 全面改版（本版，最新）**：结算采取**采销分离**——销售端与采购端各自生成对账 / 结算单据、各自确认，履约单对账完成后**不联动**生成采购端付款结算；对账单生成与确认放回**业务菜单**（销售 / 采购），开票、收票、收款、付款、办结归**财务菜单**；新增**客户来账**（客户提供对账单）与**先款后货**（预付款节点）两条流程变体；采购单「已结算」改为结算单办结时置位。本版取代 2026-11-24 版中与采销分离冲突的设计（第六节联动关系、4.1 客户侧流程步骤归属、5.6 合作商侧流程归属、七节落地顺序），其余现状盘点与法规依据继续有效。
> 文档定位：完整可落地的结算方案，供开发参照，未开发部分见第十节分期。

## 一、结论（总览）

| 事项 | 本版方案 |
|---|---|
| 总体结构 | **采销分离**：销售线（客户对账单·应收）与采购线（采购结算单·应付）各自生成单据、各自确认、各自在财务侧收付；履约单对账完成后不联动生成采购端付款结算 |
| 单据归属 | 对账单 / 结算单的**生成与确认**在业务菜单（销售 / 采购）；**开票、收票、收款、付款、办结**在财务菜单 |
| 销售端客户差异 | 淡茶先发对账单 / 客户来账 / 预存余额三种情况，同一张对账单承载，差别只在来源与付款方式 |
| 采购端合作商差异 | 签收后付款（月结 / 季结 / 周期结 / 见票结）与**先款后货**（预付款节点），同一张采购结算单承载，差别只在付款节点 |
| 单据与菜单 | 客户对账单：销售生成确认 + 财务收付开票；采购结算单：采购生成确认 + 财务收票付款；财务「对账结算」分组（合作商结算、客户对账）随迁撤并 |
| 采购单已结算 | 改为**所属结算单办结时**置位（现行实现为付款金额覆盖即置位，先款后货场景会提前置已结算） |
| 积分 | 不变：合作商「结算完成」= 付款完成（采购单已结算）且客户回款到位，两者齐备才计入 |
| 财务页面 | 发票管理、收款管理、付款管理由只读台账改为操作页；应收 / 应付管理保持只读台账；财务概览增加结算待办卡 |

## 二、总体结构（采销分离）

```
销售线（应收）：履约单确收 → 销售·生成对账单 → 销售·确认对账 → 财务·开票 + 收款 → 对账单办结 → 履约单/销售单办结
采购线（应付）：采购单签收(直发)或入库 → 采购·生成结算单 → 合作商/采购·确认 → 财务·收票 + 付款 → 结算单办结 → 采购单已结算
```

- 两条线**互不触发**：客户对账完成不生成采购端付款结算，采购端付款也不依赖客户回款。
- 两侧的单据互相**引用不互相生成**：采购结算单明细行的关联履约单号来自采购单的 `childOrderCode`，仅作对照展示与积分判定，不产生单据联动。
- 结算对象：直接销售＝客户本人；经平台销售＝平台客户，金额按销平台实价（订单价格快照，缺省回退客户档案现值）。

## 四、销售端结算（应收线）

三种客户情况的差别只落在两处：**对账单来源**与**付款方式**。开票与收款不分先后，两者都覆盖对账净额时对账单自动办结。

### 4.1 流程一：淡茶先发对账单（现流程沿用）

| 步 | 点哪里 | 做什么 | 结果 |
|---|---|---|---|
| 1 | 销售 → 销售单管理 → 履约单履约 | 对已妥投履约单点「确认收货」 | 履约状态＝已确收；订单进度直接＝结算中（G8），进入待对账 |
| 2 | 销售 → 销售单管理 → 履约单结算 → 待对账 | 勾选同一结算对象的履约单 → 「生成对账单」→ 填账期说明 | 对账单待确认；明细行 = 履约单计入金额 |
| 3 | 线下 | 对账单发客户核对回签 | 无 |
| 4 | 销售 → 客户对账 | 「确认对账」；有异议「登记异议」，调整后重新确认 | 对账单已确认，正式形成应收 |
| 5 | 财务 → 核算与其他 → 发票管理 → 待开票 | 开票登记（发票号 / 金额 / 日期，可分多张） | 对账单开票进度更新，履约单回写开票状态；发票进销项台账 |
| 6 | 财务 → 应收应付 → 收款管理 → 待回款 | 收款登记（金额 / 日期 / 方式，可分多笔） | 对账单收款进度更新，履约单回写已收款；回款进台账 |
| 7 | 无需操作 | 开票与收款均覆盖对账净额 | 对账单已办结 → 履约单已办结 → 销售单全部履约单办结后订单状态＝已办结 |

### 4.2 流程二：客户提供对账单（客户来账）

| 步 | 点哪里 | 做什么 | 结果 |
|---|---|---|---|
| 1 | 同流程一 | 确认收货 | 同上 |
| 2 | 销售 → 销售单管理 → 履约单结算 → 待对账 | 勾选来账涉及的履约单 → 「登记客户来账」：录客户对账单号、对账金额、账期 | 对账单待确认，来源＝客户来账；弹窗内并列展示淡茶侧计入金额与差异 |
| 2a | 同一弹窗 | 金额有差异：录差异调整（可正可负）+ 说明；或先「登记异议」退回客户改账 | 对账净额 = 客户确认金额 |
| 3 | 销售 → 客户对账 | 核对无误「确认对账」（本类对账单无需再发客户确认，确认即淡茶核对通过） | 对账单已确认 |
| 4~6 | 同流程一 | 开票、收款、办结 | 同上 |

登记弹窗底部两个按钮：「保存为待确认」与「核对无误直接确认」。

### 4.3 预存余额（预付客户）

| 步 | 点哪里 | 做什么 | 结果 |
|---|---|---|---|
| 预充 | 财务 → 应收应付 → 收款管理 → 预存账户 | 预收款登记：客户 / 金额 / 日期 / 方式 | 客户预存余额增加（钱包流水） |
| 消费 | 同流程一 / 二 | 生成并确认对账单，财务开票 | 同上 |
| 扣款 | 财务 → 应收应付 → 收款管理 → 待回款 | 收款登记，方式选「预存余额支付」（默认带出可扣金额） | 余额扣减，对账单核销 |
| 余额不足 | 同上 | 先用余额支付，差额再登记一笔转账 | 同上 |

- 可扣金额 = min（未收余额，预存余额）。
- 预存客户同样走对账单（沿用 2026-11-24 业务确认 3）；预收款本身不开票，开票随对账单。
- 客户档案结算方式改为选项（月结 / 季结 / 见票结算 / 预存），结算方式为预存的客户收款登记默认选「预存余额支付」。

## 五、采购端结算（应付线）

采购结算单承载全部采购单来源（合作商直发、自营以销定采、手工采购订单，G4）。付款节点分两种，默认取合作商档案结算方式（月结 / 季结 / 周期结 / 见票结 / 先款后货），生成时可改。

### 5.1 流程三：签收后付款（月结、季结、周期结、见票结）

| 步 | 点哪里 | 做什么 | 结果 |
|---|---|---|---|
| 1 | 无需操作 | 采购单已签收（直发）或已入库 | 进入待结算 |
| 2 | 采购 → 采购管理 → 采购结算 → 待结算 | 勾选同一合作商的采购单 → 生成采购结算单 | 结算单待确认 |
| 3 | 合作商工作台 → 结算管理（或采购 → 采购对账 代确认） | 合作商「确认对账」；有异议「登记异议」 | 结算单已确认，金额锁定 |
| 4 | 财务 → 核算与其他 → 发票管理 → 进项 → 待收票 | 收票登记 | 结算单收票进度更新 |
| 5 | 财务 → 应收应付 → 付款管理 → 待付款 | 付款登记（金额 / 日期 / 账户，可分批） | 结算单付款进度更新 |
| 6 | 无需操作 | 收票与付款均齐备 | 结算单已办结 → 采购单已结算 |

### 5.2 流程四：先款后货（预付款节点）

| 步 | 点哪里 | 做什么 | 结果 |
|---|---|---|---|
| 1 | 无需操作 | 合作商接单，采购单已确认且未发货 | 进入待预付 |
| 2 | 采购 → 采购管理 → 采购结算 → 待预付 | 生成采购结算单，付款节点＝发货前，带出发货前应付金额（= 结算金额 × 预付比例，默认 100%） | 结算单待确认 |
| 3 | 合作商工作台 → 结算管理 | 合作商确认对账 | 结算单已确认 |
| 4 | 财务 → 应收应付 → 付款管理 → 待付款 | 付款登记 | 结算单已预付；采购单与合作商终端显示「预付款已到账，可发货」 |
| 5 | 合作商工作台 → 订单管理 | 发货；客户确收后采购单已签收 | 无 |
| 6 | 财务 → 发票管理 → 进项 | 收票登记 | 同流程三 |
| 7 | 财务 → 付款管理（尾款）或无需操作 | 有尾款（预付比例 < 100%）的登记尾款；100% 自动办结 | 结算单已办结 → 采购单已结算 |

先款后货三条规则：

1. **不拦截发货**：未收到预付款时合作商点发货仅弹提醒，可继续（紧急放货）；已发货但未预付的采购单回到待结算，按流程三走。
2. **一张采购单同一时间只能在一张未办结的结算单内**（沿用防重复纳入校验）。
3. **结算单确认后金额锁定**，付款按发货前应付与尾款分期登记。

### 5.3 采购对账（后台代确认）

采购 → 采购管理 → 采购对账：按结算单展示待确认清单，供后台代合作商确认 / 登记异议（线下已确认的场景）；在线确认仍以合作商终端「结算管理」为主（业务待确认 4）。

## 六、财务端页面职责改版

| 页面 | 改动 | 操作 |
|---|---|---|
| 发票管理 | 只读台账 → 操作页：销项（待开票）/ 进项（待收票）两个页签 | 开票登记（已确认客户对账单）、收票登记（已确认采购结算单） |
| 收款管理 | 只读台账 → 操作页：待回款 / 回款记录 / 预存账户 | 收款登记、预收款登记、手工办结（已收款无需开票） |
| 付款管理 | 只读台账 → 操作页：待付款（含待预付）/ 付款记录 | 付款登记、手工办结（已付款无需收票） |
| 应收管理 / 应付管理 | 保持只读台账 | 点击行直达对应对账单 / 结算单 |
| 财务概览 | 新增结算待办卡：待对账履约单 / 待确认对账单 / 待开票 / 待收票 / 待回款 / 待付款 | 角标按用户确认的右上角红色数字角标样式（PartnerOrders 实装样式） |
| 对账结算分组（合作商结算、客户对账） | 删除 | 生成 / 确认迁至采购菜单；收票 / 付款迁至发票管理、付款管理 |

财务侧统一规则：**只能对已确认的对账单 / 结算单登记收付开票**（现行校验保留）；台账页「去 ×× 操作」按钮改为财务内部路由并定位到具体单据（G9）。

| 模块 | 菜单 | 调整 |
|---|---|---|
| 销售 | 销售单管理 → 履约单结算 | 保留，只负责**生成**（生成对账单、登记客户来账）。删除 发起对账结算 / 登记收款 / 登记开票 / 手工办结 四个单张操作 |

## 八、单据与状态的改动

| 对象 | 改动 |

| 合作商档案 | 增加预付比例（默认 100%） |
| 采购单 | 增加结算进度（待结算 / 结算中 / 已结算）与预付状态（待预付 / 已预付） |
| 履约单订单进度 | 确收后即＝结算中，删除「发起对账结算」动作（project_rules.md 订单进度判定同步修订） |
| 采购单已结算 | 改为所属结算单办结时置位（现行为付款金额覆盖即置位，必须改：先款后货场景发货前就会误置已结算） |

## 九、异常处理

| 场景 | 处理 |
|---|---|
| 客户 / 合作商有异议 | 登记异议 → 业务侧调整 → 重新确认。已登记开票 / 收款 / 收票 / 付款的单据金额锁定，不可再改 |
| 退货（未办结单据） | 销售退货完成自动冲减对账单（已实现）；采购退货完成自动冲减未办结结算单（新增） |
| 退货（已办结单据） | 需退款 / 红冲，本期仅在页面标记提醒，退款登记与红冲入第三期 |
| 不需要发票的客户 / 供应商 | 款项齐备后由财务手工办结 |
| 已取消的履约单 | 不进入对账单 |
| 经平台销售 | 结算对象＝平台客户，金额按销平台实价；平台客户一般走客户提供对账单 |
| 已发货但未收到预付款 | 不拦截发货（提醒）；未预付部分回待结算按签收后流程走 |

## 十、开发分期

**第一期：归位**（不改数据结构）
- 菜单按第七节调整，旧路由重定向。
- 新增采购结算、采购对账两页（内容自合作商结算迁出），采购结算覆盖自营以销定采与手工采购订单。
- 发票管理、收款管理、付款管理改为操作页；财务概览结算待办卡。
- 确收后订单进度即结算中；删除单张结算入口（履约单结算 4 个按钮、直发确认 1 个、自营工作台 1 个）。

**第二期：流程变体**
- 客户来账：来源字段、登记弹窗、差异调整。
- 先款后货：付款节点、预付比例、待预付池、采购单预付状态、合作商终端提示。
- 预收款登记迁收款管理；客户结算方式选项化。
- PO「已结算」改由结算单办结置位。

**第三期：完善**
- 退款登记、红字冲销、采购退货冲减应付、办结后退货提醒。
- 结算方式结构化（对账日 + 付款期限）后的到期 / 逾期提示。
- 客户采买平台在线对账。
