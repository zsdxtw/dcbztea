## 二、状态体系与主链

销售单状态与履约单状态分开（2026-11-23 重构）：

| 层 | 字段 / 派生 | 取值 |
|---|---|---|
| 销售单·订单状态 | `familyStatesOf().orderStatus` | 未处理（尚未送分发、未生成履约单）/ 处理中 / 已办结（全部履约单办结）/ 已取消（全部取消） |
| 销售单·进度聚合 | `familyStatesOf()` | 分发进度（未分发/分发中/分发完成）/ 履约进度（未履约/履约中/履约完成）/ 结算进度（未结算/结算中/结算完成）；x = 已完成履约单数，y = 有效履约单数（剔除已取消）；全部取消时下发/履约显示已取消且不展示 x/y |
| 履约单·分发状态 | `ExternalOrder.processStatus` → `distributeStateOf` | 待分发 / 自营待接单 / 分发比单中 / 转派待接单 / 分发已完成（5 态） |
| 履约单·履约状态 | `ExternalOrder.fulfillment.stage` → `fulfillStateOf` | 待接单 / 已接单 / 运输中 / 已妥投 / 已确收（5 态） |
| 履约单·结算状态 | `settled`（收款） × `invoiceStatus`（开票）→ `settleStateOf` | 未收款/已收款 × 未开票/已开票，组合展示如「未收款·已开票」 |
| 履约单·订单进度 | `orderProgressOf` | 分发中 / 履约中 / 结算中 / 已办结 / 已取消；判定优先级：已取消 → 已办结 → 结算中 → 分发中 → 履约中 |
| 处理阶段（兼容字段） | `ExternalOrder.dispatchState` | `unprocessed` 尚未送分发（无履约单，订单状态＝未处理）/ `dispatched` 已生成履约单 |

状态推导集中在 `src/utils/salesOrderFamily.ts`，履约时间线与 stage 口径在 `src/utils/fulfillment.ts`。

主链：

```
新建销售单（手工录入 / 平台直连推送）→ 订单状态＝未处理（销售单处理：未生成履约单）
  → 送去分发 / 拆分送分发 → 生成履约单（LY01…）→ 订单状态＝处理中
     ├─ 分发状态：待分发 → 自营待接单 / 分发比单中 / 转派待接单 → 分发已完成
     ├─ 履约状态：待接单 → 已接单 → 运输中 → 已妥投 → 已确收
     └─ 订单进度：分发中 → 履约中 →（发起对账结算）结算中 →（收款 + 开票 / 手工办结）已办结
  → 销售单下全部履约单已办结 → 销售单订单状态＝已办结
  → 任一阶段取消 → 该履约单订单进度＝已取消（分发 / 履约状态不再展示已取消）
  → 销售单下全部履约单已取消 → 销售单订单状态＝已取消
```

> 「已取消」只由订单进度承载；分发状态与履约状态不再出现已取消。
> 已确收履约单在「履约单结算」页发起对账结算，收款（未收款/已收款）与开票（未开票/已开票）为两个独立维度，组合为结算状态。

### 1.4 发货职责边界

发货执行分布在两个工作台，管理后台不承担发货录入：

| 环节 | 执行端 | 说明 |
|---|---|---|
| 自营路径发货 | 自营工作台（销售单自营 · 采购&发货） | 分仓直发 / 入库制出库，生成包裹与物流单号 |
| 转派 / 报备 / 比单路径发货 | 合作商工作台（订单管理 → 发货） | 合作商自行配送或填写物流公司 + 单号，支持按商品拆批发货 |
| 管理后台 | 仅查看与推进 | 查看包裹台账与物流、回写妥投（异常兜底 / 物流回传）、确认收货、结算、开票；不提供发货录入 |

### 1.5 销售单处理（订单进入系统的第一站）

| 项 | 规则 |
|---|---|
| 入口 | 手工录入、平台直连推送的订单一律先进入销售单处理；初始 `processStatus=unprocessed`、`dispatchState=unprocessed` |
| 履约单 | 未送分发前不生成履约单；销售单列表显示履约单数 0，展开提示「尚未生成履约单」 |
| 列表 | 不展示分发状态；商品列名为「品牌数/总数量」，显示 `x种/y份`；行操作仅「查看 / 分发 / 拆单 / 匹配报备」 |
| 查看 | 查看销售单信息、收货信息、商品明细、处理轨迹；详情页脚「关闭 / 修改 / 取消订单」 |
| 修改 | 仅手工录入单；在**同一详情抽屉内**切换到修改态（不新开抽屉/页面）；不可改字段（销售单号 / 来源 / 销售路径 / 录入时间 / 录入人 / 总金额）保留展示但置灰，可改字段切换为编辑控件；页脚为「关闭 / 取消修改 / 保存修改」，取消修改丢弃改动并回到查看态 |
| 取消 | 必须弹窗填写取消原因；取消后 `processStatus=cancelled`，不生成履约单；销售单列表保留并显示已取消；取消类按钮使用模块辅助色 |
| 拆单（预生成） | 商品明细按销售单详情样式展示；操作行依次为「快速拆单：按品牌拆单 / 按商品拆单」→「拆出」；快速拆单直接按分组生成 TAB，仅 1 个品牌或 1 种商品时生成 1 张 TAB（不再提示无法拆单）；手动填写数量后点「拆出」；TAB 可多张、可删除归还数量；未拆出的剩余数量作为末尾**虚线「剩余部分」TAB**（无剩余数量时不显示），确认后随全部 TAB 一并生成履约单；未生成 TAB 时点击「确认拆单生成履约单」弹出红字提示 |
| 分发 | 弹窗上方复用拆单预生成；未拆出的剩余数量按顺序生成末尾**虚线 TAB（剩余部分）**，可与已拆出 TAB 一样选择并单独分发；每个 TAB 可分别确定分发方式（自营 / 报备 / 比单 / 指定），点击确认后弹窗不关闭，自动切换到下一张未配置 TAB，全部确定后统一落库分发；未拆出 TAB 时针对**整张销售单**分发，分发后该销售单本身即一张履约单（编号展示为 `销售单号+LY01`），不生成子单；报备匹配需生成履约单承载按合作商的分组结果，母单保留 |
| 转去自营 | 展示各商品当前淡茶库存、分仓分布、需采购数量与采购价区间（采购规则最低/最高价） |
| 转派指定 | 第一行为必选的「本单合作模式」（差价 / 扣点），第二行为列表筛选项（地区、主营品牌、合作商类型、名称搜索）及合作商列表；合作模式是**订单与该合作商的合作模式**选择字段，不属于合作商档案属性，列表不展示合作模式列 |
| 转派-比单 | 合作商类型仅服务商 / 供应商（或两者，不含品牌商）；「本单合作模式」为必选项（差价 / 扣点）；支持参与地区范围、底价（折扣 / 具体价格）、报名时长（分钟）、评分权重（报价 / 积分），调整后立即生效 |
| 匹配报备 | 报备匹配为纯人工动作（无中间待确认状态）：人工勾选已通过报备（订单 / 商品 / 地区，按优先级排序）后直接转出首家报备合作商，生成履约单进入转派待接单；多选时全部记录为匹配信息；无货源订单报备确认后退回待分发，由平台自营或转派供货商 |
| 进度的显示 | 未送分发：销售单订单状态＝未处理，分发进度未分发、履约进度未履约、履约单数 0；已送分发但子单待分发：订单状态＝处理中，母单分发进度分发中；自营待接单 / 转派待接单阶段履约进度仍为未履约，接单后进入履约中 |

## 三、问题与优化建议

### 3.1 信息架构

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 原「新建销售单」是动作而非视图，却占用菜单位置 | 菜单层级表达的是页面而非流程 | 已解决：菜单项已移除，表单保留供「+ 新建销售单」弹窗复用（销售单列表 / 销售单处理） |
| 2 | 发货执行归属双端（合作商工作台 / 自营工作台），管理后台无独立发货页 | 管理后台无法录入物流，但包裹台账分散在履约详情中，缺少统一查看视角 | 管理后台定位为「查看 + 推进」：在履约详情提供只读包裹台账与物流跟踪，不新增发货录入页 |
| 3 | 销售退货、客户对账为静态样例数据 | 与真实订单、结算、财务完全脱节，页面操作无实效 | 退货统一接 `returnStore`；对账接订单 + 结算数据，并支持从订单发起 |
| 4 | 履约页同时承担进度与包裹明细 | 进度与单据混在一页，信息密度偏高 | 履约页以进度为主，包裹明细收进详情抽屉或折叠区 |

### 3.2 状态与口径

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 同一含义多套命名：`processed` 在分发页叫「分发已完成」，在抽屉文案中又叫「已处理」「已完成」 | 用户跨页面对不上状态 | 建立唯一状态字典，UI 文案集中管理 |
| 2 | 「已取消」与主流程节点并列在同一条流程图 | 终态与阶段混层，流程语义失真 | 主链只画阶段；已取消作为异常终态角标或独立 Tab |
| 3 | 母单聚合把报备待确认 / 比单中 / 自营待接单 / 转派待接单合并为「分发中」 | 丢失「在等谁」，无法判断该催谁 | 聚合文案带等待方，如「分发中·待合作商」「分发中·待自营」 |
| 4 | `partnerStatus` 与 `fulfillment.stage` 双写镜像 | 任一处漏写即出现「分发已完成但履约未接单」等矛盾 | 确立 `fulfillment.stage` 为单真源，`partnerStatus` 仅派生只读 |
| 5 | `fmtDT` 对缺失时分秒的数据补 `09:12:00` 演示值 | 演示值被当作真实业务时间 | 缺失统一显示 `—` |
| 6 | 分发页状态 Tab 计数不随关键词 / 筛选变化 | 搜索后数字仍是全量，误导判断 | 计数随当前搜索口径联动 |

### 3.3 分发页交互

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 同一动作分散在行内、详情抽屉 footer、工具栏弹窗三处，且时有时无（取消只在抽屉、取回只在履约页、评分定标只在工具栏弹窗） | 用户必须先判断「按钮在哪」 | 建立「行内为主、抽屉为辅」的统一操作模型，见第四节 |
| 2 | 地区与分发方式筛选仅在「全部」状态可用，选中状态后消失 | 无法组合查询「转派待接单 + 江苏」 | 筛选条件正交化，状态与地区 / 方式可叠加 |
| 3 | 拆单入口条件为 `items.length >= 1`，恒为真 | 单商品订单也显示拆单，点进去才发现无法拆 | 改为可实际拆分时才可点，并给出禁用原因 |
| 4 | 报备命中后无显式「驳回匹配」入口，只能借抽屉里语义不符的「重新分发」退出 | 错误匹配难以纠正 | 行内补「忽略报备 / 驳回匹配」并回到待分发 |
| 5 | 比单只能「评分定标」或「直接选定」，缺少流标 / 终止路径 | 无人报名时订单卡在比单中 | 增加「终止比单并转指定」 |
| 6 | 底价、报名时长、评分权重可在业务弹窗内直接改全局配置 | 配置与单据操作混层，误操作影响所有订单 | 弹窗内只读展示 + 跳转配置页 |
| 7 | 重新分发对已发货订单仅靠文案警告 | 高风险动作缺少强校验 | 二次确认（输入单号或二次勾选）+ 强制填写原因 + 审计留痕 |
| 8 | 详情抽屉对「待分发」提示「不做分发操作」，但 footer 同时提供取消 / 修改 | 文案与能力矛盾 | 统一为「抽屉可做查看与辅助操作，分发在弹窗」并修正文案 |

### 3.4 列表体验与规范

| # | 问题 | 建议 |
|---|---|---|
| 1 | 销售单列表单行工具栏堆叠 13+ 筛选器 | 折叠为「常用 + 高级筛选」，支持保存视图 |
| 2 | 分发列表行内采用「ghost → primary 选中态」 | 对齐项目统一的 `RowActions` / `RowDeleteButton` 规范 |
| 3 | 大量硬编码色值（`#0F64B5`、`#2E7D32` 等） | 改用模块 token 与语义色变量 |
| 4 | 无排序、无导出、无列配置、无 SLA 超时预警 | 补排序（时间 / 金额 / 停留时长）、导出、列设置、超时高亮 |
| 5 | 无批量操作 | 支持批量分发、批量取消、批量导出 |

## 四、履约单分发：各状态行操作矩阵

> 本节仅覆盖已送去分发、进入履约单分发的订单；未分发的销售单在「销售单处理」中操作，规则见 1.5。

> 「现状」为当前代码已实现能力；「建议」为本次评审补充项。

### 4.1 待分发 `pending`

| 操作 | 业务目的 | 现状 |
|---|---|---|
| 查看 | 核对客户、收货、商品与价格，作为分发决策依据 | 已有 |
| 分发 | 与销售单处理共用同一分发弹窗（上方拆单预生成 + 剩余部分虚线 TAB + 四方向「转去自营 / 转派-报备 / 转派-比单 / 转派指定」）；每个 TAB 可分别确定分发方式，确认后弹窗不关闭并继续下一张，全部确定后在同一销售单下拆出 1 张或多张履约单并逐张分发；未拆出 TAB 时针对当前履约单本身 | 已有 |
| 拆单 | 按品牌 / 商品快速拆单或按数量手动拆单，先预生成履约单 TAB；仅 1 个品牌 / 1 种商品时快速拆单生成 1 张 TAB；未拆出的剩余数量作为末尾虚线「剩余部分」TAB（无剩余时不显示）；确认后生成子履约单 | 已有（与销售单处理同款预生成设计） |
| 修改 | 仅手工录入单纠正收货信息与商品数量 | 已有（仅手工单） |

### 4.6 分发已完成 `processed`

按履约子阶段拆分：

| 子阶段 | 应支持操作 | 目的 |
|---|---|---|
| 已接单未发货 | 查看、催发货、查看采购与包裹、重新分发（强警告）、取消订单 | 发货前仍可干预；催办保障时效 |
| 已发货 / 在途 / 已妥投 | 查看、物流跟踪（包裹级）、推进妥投（异常兜底 / 物流回传）、确认收货（全部妥投后）、重新分发（强警告 + 二次校验） | 推进履约闭环与确收节点 |
| 已确收 | 查看、结算（按时 / 超时，按包裹）、登记开票（部分 / 全额）、发起退货、导出对账单 | 完成资金与售后闭环 |
| 全局 | 查看 / 导出包裹台账、查看母子单家族 | 仓配作业与追溯 |

现状：行内仅「查看 / 重新分发」，其余均在抽屉 footer；已发货后仍可取消，应禁止或仅超管可强制。
